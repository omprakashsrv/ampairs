# Contract — Demand Forecast `/sync` (pull-only)

Canonical offline-sync **pull** feed for `DemandForecast`. Forecasts are server-generated by the nightly
batch (R5) and are **read-only on the client**, so this resource exposes the `GET /sync` half of the
canonical contract only — there is no client `POST` (the documented exception, like `tax`/`file` are
off-contract for their own reasons). → FR-015/FR-019, plan P2, offline-sync skill.

---

## GET `/analytics/v1/forecasts/sync`

Incremental, paginated pull of forecast rows updated since the client's checkpoint. Includes rows the
server has retired (so the device can drop stale forecasts), exactly like the standard `/sync` pull.

**Headers**: `Authorization: Bearer <jwt>`, `X-Workspace-ID: <workspace>`.

**Query params** (snake_case):
| Param | Type | Default | Notes |
|---|---|---|---|
| `last_sync` | ISO-8601 instant | (omitted on first sync) | Return rows with `updated_at > last_sync`. Sent only when non-blank. |
| `page` | Int | 0 | Zero-based page index. |
| `size` | Int | 100 | Max 100 (server caps). |
| `sort_by` | String | `updatedAt` | Fixed to `updatedAt` for stable incremental paging. |
| `sort_dir` | String | `ASC` | Ascending so the checkpoint advances monotonically. |

**200** `ApiResponse<PageResponse<DemandForecastResponse>>`:
```json
{
  "success": true,
  "data": {
    "content": [
      {
        "uid": "DFC20260627000001ABCDEF...",
        "product_id": "PRD20260101ABCDEF...",
        "period_start": "2026-07-01",
        "horizon": 1,
        "mean_qty": "842.000",
        "std_dev_qty": "73.500",
        "method": "HOLT_WINTERS",
        "confidence": "HIGH",
        "generated_at": "2026-06-27T03:30:00Z",
        "updated_at": "2026-06-27T03:30:00Z",
        "active": true
      }
    ],
    "page_number": 0, "page_size": 100, "total_elements": 1, "total_pages": 1,
    "first": true, "last": true, "has_next": false, "has_previous": false, "empty": false
  },
  "error": null
}
```

**Client reconciliation (`DemandForecastSyncDelegate`, PULL-ONLY)**:
1. Page with `last_sync` = stored checkpoint until `has_next == false`.
2. Upsert each row into the read-only `DemandForecastEntity` mirror (`synced = true`); rows reported
   `active = false` are removed.
3. Advance the `SyncEntity.DEMAND_FORECAST` checkpoint to `max(updated_at)` seen.
4. **No push** — there is no local write path; the delegate implements `pull` only.

**Errors**: `400` malformed `last_sync`; `401` missing/expired token; `404`/reject when `X-Workspace-ID`
is absent (`SessionUserFilter`).

```kotlin
)
fun DemandForecast.asResponse(): DemandForecastResponse = DemandForecastResponse(...)
```

## Demand signal (not an endpoint — module boundary, R6)

In addition to this pull feed, the batch publishes `DemandForecastUpdatedEvent` and exposes a public
`DemandSignalService` (avg daily demand + variability per product) for **in-process** consumption by
feature 027 (reorder point/safety stock) and inventory (spec 014). Analytics never writes those modules'
tables (FR-018 / Principle IX).
