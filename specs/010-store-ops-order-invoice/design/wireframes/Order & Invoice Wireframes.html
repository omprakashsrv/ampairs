Store Ops — Order & Invoice

One line-item pattern, two entry points. An Order is the working sales doc; an Invoice is the legal GST document. Same anatomy, same totals math, adaptive across phone / tablet / desktop, offline-first. These are deliberately rough wireframes to agree structure & flow before we go hi-fi M3.

Reading these: this is a map of the design space, not pixels. Colour is used only to mark roles — violet = primary action / focus, amber = sticky / attention, green = synced/ok, red = error/destructive.

Adaptive rule of thumb

Phone · single-pane

Navigate between list → editor → line sheet → picker. One job on screen at a time. Bottom sheets for editing. Sticky totals collapse to a bar.

Tablet · two-pane

List-detail. Editing happens in the right pane; line editor expands inline instead of a modal. Totals as a pinned band.

Desktop · two-pane + keyboard

Line grid is a spreadsheet: Tab across cells, Enter adds a line, ⌘S saves. Totals pinned right.

Notes

e
Conversion hint is live. Shows the multiplier, the rescaled per-unit price, and the unit’s allowed decimal places — so staff trust the number before committing.
